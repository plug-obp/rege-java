# Rege 2.0.0

Reader-infra now uses a shared source-coordinate contract compatible with LSP's
default UTF-16 position encoding. This is a breaking change from version 1.x.
All repository modules use the coordinated version `2.0.0`.

## Coordinate migration

- `Position.line()` and `Position.column()` are now zero-based. Columns and
  absolute offsets count UTF-16 code units. `Position.start()` is `(0, 0, 0)`.
- Ranges remain half-open: start inclusive, end exclusive. Remove the `- 1`
  adjustments previously needed in LSP adapters, and update literal positions
  and structured diagnostic expectations.
- New `SourceText` indexes original text independently of syntax trees. It
  recognizes LF, CRLF and CR, converts Unicode code-point indices (such as
  ANTLR's) to UTF-16 offsets, and provides line bounds and LSP position lookup.
  EOF is a regular position, including an empty final line after a newline.
- `Peekable` uses the same coordinate index, so parser positions and source
  tooling agree. Supplementary Unicode characters occupy two UTF-16 code units.

## Optional source evidence

`ParseError.range()` may now be null when no source evidence is available.
Unlocated diagnostics preserve their severity, message and optional code;
formatting does not invent a location or expose a source excerpt. Consumers must
handle missing ranges before producing LSP diagnostics, which require a range.

Human error rendering stays one-based. This display-only conversion does not
change stored coordinates or `Position`/`Range` string representations. Source
excerpts handle every supported line ending, and multiline underlines stop at
the displayed line's end.

## Artifacts and validation

The release publishes `org.obpcdl:reader-infra:2.0.0`,
`org.obpcdl:rege-core:2.0.0`, and `org.obpcdl:rege-modelchecker:2.0.0` to the
repository's GitHub Packages registry, with binary, source and Javadoc JARs.

The full JDK 23 test suite passes: **481 tests** (118 reader-infra, 355 rege-core,
8 rege-modelchecker), including regressions for zero-based positions, UTF-16,
all three newline forms, EOF, absent source evidence and diagnostic rendering.

See the [reader-infra migration guide](../../reader-infra/README.md#migrating-from-1x-to-200)
for API examples.
